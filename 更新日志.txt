v10.5.0 (2026-05-17)
----------------------------------------
[EN]
[Bug Fixes]
• Added missing `import base64`: encrypt_token() and decrypt_token() used base64.b64encode/
  base64.b64decode but the module was never imported, causing NameError at runtime
• Fixed upload_release_asset bypassing NetworkManager: was using bare requests.post() with no
  retry, proxy, or timeout support; changed to self._net.request()
• Fixed os.startfile being Windows-only: _open_log_dir now uses platform detection
  (os.startfile on Windows, `open` on macOS, `xdg-open` on Linux)
• Fixed _batch_upload hardcoded branch "main": now reads the branch value from the upload tab
  settings, falling back to "main" if empty
• Fixed _show_loading event loop re-entry: changed root.update() to root.update_idletasks()
  to prevent recursive event handling

[Refactoring]
• Extracted _run_async(label, fn, on_done=None) helper: eliminates 36 copies of the
  show_loading → threading.Thread → try/except/finally → hide_loading boilerplate,
  reducing the codebase by ~260 lines
• Extracted _parse_owner_repo(var) helper: eliminates 18 copies of the
  validate_owner_repo → split("/", 1) pattern
• Extracted _populate_treeview(tree, rows) helper: eliminates 8 copies of the
  tree.get_children() → delete → insert loop

[Code Cleanup]
• Removed unused import io (never referenced in the file)
• Removed unused import ThreadPoolExecutor (never referenced in the file)
• Removed unused method GitOps.check_ssh() (defined but never called)
• Removed unused method GitOps.get_submodules() (defined but never called)
• Extracted 15 named constants replacing magic numbers: MAX_LOG_SIZE, MAX_LOG_FILES,
  MAX_HISTORY, HTTP_TIMEOUT, HTTP_RETRIES, RETRY_AFTER_DEFAULT, REPOS_PER_PAGE,
  SEARCH_PER_PAGE, ISSUES_PER_PAGE, WINDOW_SIZE, WINDOW_MIN_SIZE, SIDEBAR_WIDTH,
  ICON_SUBSAMPLE, WEIXIN_SUBSAMPLE

[Type Annotations]
• Added type annotations to all public methods of PlatformAPI (30 methods)
• Added type annotations to all public methods of GitOps (23 methods)
• Added type annotations to key App methods (log, run, _log_to_ui)
• Added `from __future__ import annotations` for forward reference support

v10.4.0 (2026-05-13)
----------------------------------------
[EN]
[Performance Optimization]
• GradientButton: Removed redundant first-pass gradient loop (original code drew two passes;
  the first was completely overwritten by the second)
• GradientButton: Added color cache (_cached_colors); reuses pre-computed gradient list when
  colors are unchanged, significantly reducing string-parsing overhead on hover

[Bug Fixes]
• Fixed missing username attribute in PlatformAPI: falling back to self.api.username during
  post-fork clone caused AttributeError; initialized properly and assigned in get_user()
• Fixed NetworkManager returning None after consecutive rate-limiting: after 3×429 responses
  the function implicitly returned None; changed to save the last response and return it,
  preventing .status_code crash in callers
• Fixed list_repos parsing JSON three times: each paginated call invoked r.json() three times;
  changed to cache result in data
• Fixed EXE startup crash: token migration write exceptions no longer block startup;
  changed to silent try/except skip

[Encapsulation Improvements]
• GitOps: Added pull_unrelated(path, remote, branch): encapsulates --allow-unrelated-histories pull
• GitOps: Added pull_with_strategy(path, remote, branch, strategy): encapsulates pull with merge strategy
• Eliminated encapsulation leak of directly calling private git._run(["pull",...])
  in _do_upload and _do_commit_push

[Code Quality]
• Merged App.log and _log_to_ui: thread-safe logic unified in _log_to_ui;
  log() only formats and delegates
• _get_theme adds _normalize_theme(): uniformly fills missing fallback keys for all themes
  (sidebar_bg/card_bg/tooltip_bg etc.), eliminating scattered .get("key", default) calls
• NetworkManager: merged Timeout + ConnectionError retry logic, eliminating duplicate code blocks
• Removed duplicate import time inside _do_fork (already imported at top level)

[Thread Safety]
• _do_upload, _do_create_repo: moved desc/priv/lic/msg/gitignore reads to main thread
• _do_commit: moved ud_msg read to main thread
• _do_push: moved ud_force read to main thread
• _do_commit_push: moved ud_msg/ud_force reads to main thread
• _load_issues: moved is_state read to main thread
• _load_pulls: moved pr_state read to main thread

[Security]
• Token encrypted local storage: machine-bound XOR+base64 encryption scheme (_get_machine_key);
  tokens no longer stored as plaintext in config files; automatically decrypted on restart,
  no need to re-enter
• On exit, only clears memory (_cleanup no longer overwrites disk);
  encrypted token auto-restores on next startup

v10.4.0 (2026-05-13)
----------------------------------------
【性能优化】
• GradientButton：删除冗余第一遍渐变循环（原始代码绘制了两遍，第一遍完全被第二遍覆盖）
• GradientButton：新增颜色缓存（_cached_colors），colors 不变时复用已计算的渐变列表，
  大幅减少 hover 时的字符串解析开销

【Bug 修复】
• 修复 PlatformAPI 缺少 username 属性：Fork 后克隆时回退到 self.api.username 会
  AttributeError，补全初始化并在 get_user() 中赋值
• 修复 NetworkManager 连续限流后返回 None：3 次 429 后函数隐式 return None，
  改为保存最后一个响应并返回，避免调用方 .status_code 崩溃
• 修复 list_repos 三次重复解析 JSON：每次分页调用 r.json() 三次，改为缓存到 data
• 修复 EXE 启动崩溃：Token 迁移写入异常不再阻断启动，改为 try/except 静默跳过

【封装改进】
• GitOps 新增 pull_unrelated(path, remote, branch)：封装 --allow-unrelated-histories 拉取
• GitOps 新增 pull_with_strategy(path, remote, branch, strategy)：封装带合并策略的拉取
• 消除 _do_upload 和 _do_commit_push 中直接调用私有 git._run(["pull",...]) 的封装泄漏

【代码质量】
• 合并 App.log 与 _log_to_ui：线程安全逻辑统一到 _log_to_ui，log() 只负责格式化后委托
• _get_theme 增加 _normalize_theme()：统一为各主题补全缺失的 fallback key
  （sidebar_bg/card_bg/tooltip_bg 等），消除散落在代码各处的 .get("key", default)
• NetworkManager 合并 Timeout + ConnectionError 重试逻辑，消除重复代码块
• 移除 _do_fork 内的重复 import time（顶层已导入）

【线程安全】
• _do_upload、_do_create_repo：desc/priv/lic/msg/gitignore 读取移至主线程
• _do_commit：ud_msg 读取移至主线程
• _do_push：ud_force 读取移至主线程
• _do_commit_push：ud_msg/ud_force 读取移至主线程
• _load_issues：is_state 读取移至主线程
• _load_pulls：pr_state 读取移至主线程

【安全】
• Token 加密本地存储：使用机器绑定的 XOR+base64 加密方案（_get_machine_key），
  配置文件中不再明文保存 Token，重启后自动解密恢复，无需重新输入
• 退出时只清内存（_cleanup 不再覆写磁盘），加密 Token 在下次启动时可自动还原
